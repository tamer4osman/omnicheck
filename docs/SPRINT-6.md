## Delivered

### 1. Fuzz targets + corpus hardening (WBS 5.1)

`tests/test_fuzz.c` (20th suite binary) runs three deterministic layers,
all reproducible by committed seed and bounded in time:

- **Layer 1 - seeded mutation fuzz, in-process.** A committed seed table
  (12 seeds x 4 cases) drives six byte-level mutation operators (flip,
  insert, truncate, block-duplicate, NUL-inject, byte-storm) over the
  example corpus, one file per grammar, and scans each mutated tree
  through `oc_scan_run` TWICE in the same process: findings must stay
  canonically sorted, severities bounded, and the two report writes must
  be BYTE-IDENTICAL. In-process double-scanning is the point: a fresh
  process per run masks stack-garbage nondeterminism (it did -- see the
  bugs below).
- **Layer 2 - committed adversarial corpus** (`tests/fixtures_fuzz/`,
  generated by `scripts/gen_fuzz_corpus.py`, byte-stable across cells):
  19 source files attacking one parser/pipeline assumption each (NUL
  bytes, invalid UTF-8, BOM, CR/CRLF/LF mixed, unterminated constructs,
  900-deep nesting, 2000 unclosed braces, 600 KB single line, 2000
  functions, 100 KB identifier, unicode identifiers, empty files,
  missing trailing newline, comment-only files) run through the real
  binary, singly and as one tree: exit codes stay in {0,1,2}, no crash,
  and every exit-2 carries a stderr warning PLUS named `parse_errors`
  records in the report -- the no-silent-partial-analysis contract under
  attack.
- **Layer 3 - loader fuzz.** Ten malformed JSON inputs (truncated
  coverage, 1e999 exponents, wrong types, nested `[x5000]` bombs, NUL in
  schema strings, duplicate keys) go through the strict parser
  in-process and through the coverage and OSV loaders via the CLI:
  honest error or complete DOM, never a crash. Plus a compat self-compare
  over garbage trees (verdict, never a segfault).

Budget: Release cell ~7 s, sanitize cell ~90-145 s (ASan on the stress
files; the hardening is the deliverable, the cost is recorded). Suite
count 19 -> 20; full matrix green (below).

### Bugs the fuzz harness caught on its first runs (kept as evidence)

1. **NULL-config dereference in the library seam.** `oc_config_get_int`
   dereferenced `c` unguarded; `oc_dup_build` reads three keys through
   it, and `oc_scan_run` accepts `opt.cfg == NULL`. Every CLI path
   builds a config, so the crash was invisible from the CLI -- the fuzz
   harness hit it within one second (`pass.c` fixed: NULL config =
   defaults, at the single choke point all passes read through).
2. **Uninitialized `osv_snapshot_date` = nondeterministic reports.**
   `oc_scan_run` initialized the result field-by-field and every field
   added after Sprint 4 (`osv_snapshot_date`, `manifests_scanned`,
   `leaderboard`...) was missed. With no `--osv-snapshot`, the first
   in-process scan emitted `"osv_snapshot_date":"\u001e\f"` (stack
   garbage) and the second omitted the block -- byte-different reports
   in the SAME process at -O3, while ASan/Debug happened to pass. CLI
   runs never saw it because each process start reproduces the same
   stack garbage. Fix (`scan.c`): memset the whole result first, then
   run the per-field inits -- Sprint 0's BUG-1 lesson ("every struct
   field added later needs an init-site review") applied structurally.
3. **Harness-side, honestly recorded:** the first capture helper used a
   capped pipe and the stress corpus's multi-MB reports killed the child
   with SIGPIPE (exit 141). Replaced with file capture; the ENGINE was
   innocent, the test was not.

### 2. Determinism audit on the full corpus (GA criterion)

`scripts/acceptance/determinism_audit.py`: regenerates the 10k-file
corpus with the committed generator (content digest recorded:
`a4ec9ac931be3e26...`), then scans it with EVERY build cell -- gcc/clang
x Release/Sanitize -- Release cells twice each (the repeated-run claim),
sanitize cells once (cross-preset identity), pinned to one core
(`taskset -c 0`).

Result: **6 runs (4 cells), 1 digest** -- the 14.9 MB report is
byte-identical across compilers, optimization/preset levels and
sanitizer instrumentation (the first audit run, 8 runs with both
sanitize cells doubled, produced the same single digest).
Perf budgets re-affirmed on Release cells: worst single-core wall
**10.88 s** (sprint gate 90 s, M2 target 60 s -- both PASS with 5x
margin; sanitize cells are recorded for byte-identity, never for wall
time -- ASan cost is not engine cost). Evidence:
`docs/evidence/determinism_audit.json`.

### 4. Packaged binaries + npm shim

- `scripts/package.sh`: release tarball `omnicheck-<version>-linux-<arch>.tar.gz`
  with install layout (`bin/oc`, `packs/`, LICENSE,
  THIRD_PARTY_NOTICES.md, README.md) + sha256 manifest (tarball AND
  binary), then a smoke that extracts the tarball and proves the
  packaged binary's report is BYTE-IDENTICAL to the repo build's on the
  examples corpus. Current artifact: `omnicheck-0.3.0-linux-x86_64.tar.gz`.
- `npm/` shim package (`bin/oc-shim.js`): resolves the native binary
  through OC_BIN env -> shipped `bin/native/oc` -> optional platform
  packages `@omnicheck/oc-linux-{x64,arm64}`; execs with inherited stdio
  and the child's EXACT exit code (0/1/2 semantics pass through npm
  unchanged); honest exit 2 with an actionable message when nothing
  resolves. Verified in-session through the native path (byte-identical
  report to the direct build, same arguments) and the OC_BIN path, plus
  the missing-binary error leg.
